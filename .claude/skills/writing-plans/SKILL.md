# 계획 아티팩트 기록

네이티브 plan mode가 설계·승인을 담당한다. 이 스킬은 그것을 **대체하지 않고**, 승인된 계획을
리포 안에 영구 기록해 실행 세션·리뷰어·미래의 자신이 참조하게 한다.

## 언제

- 여러 슬라이스·스텝에 걸치거나 여러 세션에 나눠 실행할 기능. (단일 파일 소규모 변경은 불필요.)

## 어디에

- `docs/plans/YYYY-MM-DD-<feature>.md`. 날짜는 작성일.
- ADR(`docs/adr/`)과 **역할 분리**: ADR은 "왜"(되돌리기 어려운 결정), plans는 "무엇을 / 어떻게"(실행 계획).

## 무엇을

- **Context** — 왜 이 변경을 하는가(문제·의도한 결과).
- **Task 분해** — 각 task에 정확한 파일 경로, 건드리는 **인터페이스 시그니처**, 체크박스 스텝,
  해당 **FSD 레이어**를 명시한다. 플레이스홀더("적절히 처리")가 아니라 구체적으로.
- **검증** — 각 task를 어떻게 테스트하는가(`pnpm test`·게이트·수동 확인).
- 실행하며 task 상태를 체크(`[ ]` → `[x]`)해 진행을 추적한다.
