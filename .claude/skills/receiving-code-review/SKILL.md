# 코드 리뷰 받기

`code-review` 스킬·`code-reviewer` 서브에이전트가 리뷰를 **주는** 쪽이라면, 이 스킬은 **받는** 쪽
규율이다. 피드백을 기술적으로 엄밀히 평가하고 한 번에 하나씩 반영한다.

## 5단계

1. **읽기** — 모든 코멘트를 끝까지 읽는다.
2. **이해** — 무엇을 왜 지적했는지 파악한다. 불명확하면 **STOP** — 명확해지기 전엔 구현하지 않는다.
3. **검증** — 이 코드베이스(FSD 경계·ADR·기존 동작)에 기술적으로 맞는 지적인가? 반영하면 기존
   기능이 깨지지 않는가? 리뷰어가 전체 맥락을 아는가?
4. **평가** — 우선순위: Blocking(깨짐·보안) → 단순 수정(오타·import — 대부분 eslint / format 훅이 처리) → 복잡 변경.
5. **응답** — 한 번에 한 항목씩 반영한다.

## 금지

- **수행적 동의 금지** — "말씀이 전적으로 맞습니다!" 류로 받지 말 것. 동의하면 사실만 진술하거나
  조용히 수정하고, 동의하지 않으면 **기술적 근거로 반박**한다.
- 검증 없이 모든 지적을 무비판 반영(외부 리뷰어가 이 코드베이스 맥락을 모를 수 있다).
- 한 커밋에 무관한 여러 피드백을 뭉뚱그려 반영.
